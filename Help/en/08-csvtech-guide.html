    Chapter 8 CSVTech Technical Guide

    This chapter follows the sample CSV structure more closely. It keeps the template names, the field meanings, and the sample rows so you can compare your file against the documented format.

    8.1 What CSVTech Is

    CSVTech uses a CSV file to describe a customized Technology File. You can organize layer data in a spreadsheet-like format and reuse it for import, sharing, later editing, or template-based extension. All supported Technology Files can be converted to CSV Tech for secondary editing and sharing. If you do not have a suitable Technology File, you can manually edit CSV Tech according to the known stackup and then import the GDS file.

    8.2 Two Templates at a Glance

    Template Chinese description When to use
    CSVTech_overlapping_template.csv Explicit dielectric definition, with dielectric and metal/via defined separately Best when you want to describe dielectric details in full
    CSVTech_laminate_template.csv Implicit dielectric definition, with less input data Best when you want to organize the stackup quickly

    8.3.2 Reading Rules

    1. LayerName is the stackup layer name used by 3D Layout and should be present.
    2. Type meanings: C = Conductor/Metal layer, V = Via layer, D = Dielectric layer, I = Insulating layer.
    3. Via Group and SnapViaGroups are implemented on all Via layers.
    4. Insulating layer defines TSV insulation thickness and must have a LayerName defined in Via Layers.
    5. LayerMap indicates the layer mapping in GDS.
    6. Conductor/Metal and Via layers must have LayerMap value or they will be ignored.
    7. Multiple LayerMap mappings can be written in one layer, separated by spaces, for example 86;0 85;0.
    8. TextLayerMap indicates the layer used to extract net list in GDS.
    9. Thickness is the layer thickness, and the default unit is um.
    10. Height indicates the position of the layer in the stackup.
    11. All Height values refer to the lower boundary of the layer.
    12. If dielectric Height is omitted, the height is accumulated from the dielectric thickness in reverse order.
    13. If metal and via Height are omitted, the height is accumulated from metal and via thickness in reverse order.
    14. The last dielectric layer is the origin; all D/C/V Height values reference this origin, and negative values are accepted.
    15. LowerLayer and UpperLayer define the start and end layers of a via layer.
    16. If LowerLayer and UpperLayer are not given, adjacent layers are used.
    17. LowerLayer and UpperLayer determine via thickness and have higher priority than via Thickness.
    18. DK, DF, and Cond are used to set material properties.
    19. TC1, TC2, and Tref are temperature coefficients for conductivity corner analysis.
    20. Temperature-dependent material will be used if UseTemperatureDependMaterial is checked in the GUI.

    8.3.3 Notes

    #Note:
1 lines beginning with # will be considered comments
2 lines without Type value will be ignored
3 Type definition, C : Conductor/Metal layer, V : Via layer, D : Dielectric layer, I : Insulating layer
4 Conductor/Metal and Via layer must have LayerMap value, or will be ignore
5 Dielectric Layer Height is optional, if present the dielectrics will be reorder by the height
6 Conductor/Metal layer Height is must be given in overlapping templete, it will be reorder by Height
7 Via layer Height and Thickness will be definited by LowerLayer and UpperLayer
8 Insulating layer is designed to define TSV insulation thickness, it must have a LayerName that have defined in Via Layers, or will be ignore
9 All Height indicate the lower of the layer
10 All length unit is default in microns

    8.5 How to Choose

    1. CSVTech_laminate and CSVTech_overlapping are both templates for GDS import, and you can choose the one that fits your case best.
    2. CSVTech_laminate defines dielectric layers implicitly, so it needs less input data and is better when you want to organize the stackup quickly.
    3. CSVTech_overlapping defines dielectric layers explicitly, so it needs more input data and is better when you want to describe dielectric details in full.
    4. Fill TextLayerMap if you need net extraction from GDS text.
    5. Start from CSV if you want to build a technology file step by step and fill in mapping later.

    8.6 Recommended Workflow

    1. Copy the template file first.
    2. Fill LayerName and LayerMap according to the target process revision.
    3. For the overlapping template, complete dielectric, metal, and via rows separately.
    4. For the laminate template, confirm the stackup first and then fill metal/via rows.
    5. Save the CSV and use it directly as the Technology File in the CSVTech flow.
